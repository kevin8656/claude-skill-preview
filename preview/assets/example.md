# 【虛構範例】範例烘焙坊 Notion 系統提案

```首屏
眉標｜虛構範例｜接案提案
結論｜用 Notion 收齊訂單、庫存、排班，6 週上線
補充｜現在三件事分散在 LINE 群組、紙本筆記和 Excel，老闆每天要花將近 1 小時對資料。
要你｜2 題｜選方案、勾加購，題目就在方案那一段下面｜#q1
要你｜1 件｜看完按「複製結果」傳給我｜#todo
期限｜這份報價有效 14 天；收到你的回覆後，我 2 天內寄合約
```

> [!注意] 這是示範用的假提案
> 店名、需求、金額都是編的，只是讓你看預覽頁長什麼樣子。

```數字
6 週｜上線時間｜從簽約隔週開始算
3 個｜整合的資料庫｜訂單、庫存、排班
1 小時 → 10 分鐘｜每天對資料的時間｜依目前流程估算
48,000 元｜建議方案報價｜含 2 次教學
```

## 差在哪｜三件事從分散三處，變成收在同一個地方

```對照
現在 → 改完後
接訂單｜LINE 訊息一則一則翻 → 表單送出自動進訂單資料庫
看庫存｜打開 Excel 手動加減 → 訂單完成自動扣庫存
排班｜紙本筆記拍照傳群組 → 日曆檢視，每個人只看自己的班
```

## 怎麼組成｜表單收資料，資料庫自動連動，儀表板一眼看完

```架構
入口｜訂單表單、員工手機
↓ 資料寫進
資料庫｜訂單 → 庫存、排班
↓ 整理成
儀表板｜今日訂單、低庫存提醒、本週班表
```

## 時程｜6 週上線，現在在第 1 週的提案確認

```時間軸
✅ 第 0 週｜需求訪談｜已完成，確認三大痛點
👉 第 1 週｜提案確認｜就是這一頁
第 2 到 3 週｜建置資料庫｜訂單與庫存先做
第 4 週｜排班與儀表板｜接上日曆檢視
第 5 週｜試營運｜店內實際跑一週
第 6 週｜教學與交接｜2 次線上教學
```

## 方案｜建議選中間的方案，排班一起做最省事

> [!注意] 報價不含 Notion 付費方案
> 店內 3 人使用，Notion Plus 方案每月另計，由店家自行訂閱。

```題目
選哪個方案｜單選
說明｜三個方案差在做到哪一步，報價都含 2 次教學
★ 建議方案：訂單＋庫存＋排班｜48,000 元｜三件事一次收齊，老闆不用再對班表
基本方案：訂單＋庫存｜36,000 元｜排班照舊用紙本，之後要加再另外報價
進階方案：再加會員集點｜68,000 元｜工期多 2 週，第 8 週上線
```

```題目
要不要加購｜複選
說明｜可以之後再加，現在勾的會一起寫進合約
月報表：每月營收與熱銷品項｜6,000 元｜月初自動產出，不用自己算
新訂單通知：店長手機收到提醒｜5,000 元｜忙的時候不會漏單
✕ 先都不加
```

## 風險｜員工上手與資料搬家都有對策，節慶檔期要避開

| 項目 | 現在 | 改完後 |
|---|---|---|
| 員工不會用 | 只有老闆會用 Excel | 試營運週每天 10 分鐘帶操作 |
| 資料搬家 | Excel 欄位不一致 | 由我整理後一次匯入 |
| 進度狀態 | {黃:等你確認方案} | {綠:確認後隔週開工} |

> [!風險] 試營運週如果遇到節慶檔期，建議延後一週
> 忙的時候換系統，員工容易回頭用舊方法。

## 合作方式｜四步走完，每週五都看得到進度

```步驟
確認方案｜答完這頁的題目，回傳給我
簽約付訂｜訂金 50%
每週回報｜每週五傳一次進度預覽頁
驗收交接｜試營運沒問題付尾款
```

```明細 每週回報會看到什麼
- 這週做完的功能，附畫面截圖
- 下週要做的事，和需要你提供的資料
- 和你一樣用這種預覽頁，框選任何一句就能留意見
```
