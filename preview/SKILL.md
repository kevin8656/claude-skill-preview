# 預覽：可框選評論的 HTML 頁

把任何計劃、提案、草稿或完稿，變成一頁手機上也好審的 HTML：首屏講完結論和要讀者做的事，題目可以直接按，任何一段字都能框選留評論。看完按「複製結果」（或工具列的「複製全部」），作答和評論會變成一份 markdown，貼回對話就能照著改。

## 這個技能的檔案在哪

本檔所在的資料夾就是技能資料夾（下面寫成 `$SKILL_DIR`）。每次執行指令前先設定它：

```bash
SKILL_DIR="${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/preview}"
[ -f "$SKILL_DIR/scripts/md-to-preview.py" ] || SKILL_DIR="$(cd "$(dirname "$(find "$HOME/.claude/skills" .claude/skills -path '*/preview/scripts/md-to-preview.py' 2>/dev/null | head -1)")/.." && pwd)"
echo "$SKILL_DIR"
```

- 只需要 Python 3.9 以上，全部用標準函式庫，不用 pip 安裝任何東西。
- macOS 用 `python3`；Windows 若沒有 `python3` 指令，改用 `python` 或 `py`。
- 找不到技能資料夾就停下來告訴使用者，請他確認 `preview` 資料夾放在 `~/.claude/skills/` 底下，不要自己另外寫一套評論功能。

| 檔案 | 用途 |
|---|---|
| `scripts/md-to-preview.py` | 主要產生器：md 轉預覽頁 |
| `scripts/convert/inject.py` | 已經排好版的 HTML，只加上評論功能 |
| `scripts/convert/shell.py` | 外殼：組整頁、首屏、題目卡、段落、進度列（產生器會自己呼叫） |
| `scripts/convert/shell-navy.css` | 外殼與新元件（首屏、題目卡、待辦、進度列、浮動目錄）的樣式 |
| `scripts/convert/runtime.js` | 頁面互動：作答、進度、浮動目錄、匯出。不含評論功能 |
| `scripts/convert/visuals.py`、`flow.py`、`tables.py` | 圖像元件、流程圖、表格轉換與版面體檢（產生器會自己呼叫） |
| `scripts/convert/components.css`、`visuals.css` | 流程卡片、表格、圖像元件的樣式 |
| `assets/preview-comment-overlay.html` | 框選評論介面 |
| `assets/preview-tokens.css` | 色、字、間距；想改外觀改這裡 |
| `assets/fonts/` | 自帶字型 Noto Sans TC、Geist、Geist Mono（SIL OFL 授權） |
| `assets/example.md` | 完整範例：一份虛構的接案提案，所有寫法都用到 |

## 先判斷要不要開頁

| 情況 | 給什麼 |
|---|---|
| 一句話答得完的問題 | 對話裡直接答，不開頁 |
| 只有一個是非題或二選一 | 對話裡出選擇題：選項標 A、B，建議的排第一並寫清楚後果，使用者回一個字母就好 |
| 三項以上要逐項決定，或要比較幾種寫法 | 預覽頁加題目卡 |
| 計劃、提案、報告、步驟說明、要討論的事 | 預覽頁，對話只留一兩句加檔案路徑 |
| 合約、完稿文案、逐字稿這類要逐句看的原文 | 預覽頁的原文審稿版（加 `--no-lint`） |

- 一頁只放一件事。要確認的事有好幾件，排成順序一次遞一頁，結尾講「下一件是什麼、還剩幾件」。
- 修改中途不要零碎丟頁，自己做完、檢查完再整理成一頁給他看。

## 規則一：評論一律是「框選式」

使用者說「加評論」「可以評論的版本」，指的都是像 Google Docs 那樣「框選任意文字 → 留評論」，不是每段旁邊放一個輸入框。這個技能的評論介面就是框選式，直接用，不要另外做。

## 規則二：一律跑產生器

- 預覽頁一律用 `scripts/md-to-preview.py`（md 來源）或 `scripts/convert/inject.py`（已排好版的 HTML）產出。
- **不要手刻整頁、不要手抄 CSS、不要自己寫勾選、進度、目錄、匯出的程式。** 不要用 Google Fonts 等外部字型服務。
- 缺元件（下面沒有的圖表，例如進度條、量表）時不手刻，先用現有元件表達（進度寫成 `數字`、程度用色標或表格），並在回報裡講一句「缺什麼元件、用了什麼代替」。
- 想改外觀就改 `assets/preview-tokens.css`（色、字、間距）或 `scripts/convert/shell-navy.css`（外殼與新元件），重跑產生器。
- 頁面只有一套樣子：深藍首屏、暖米底、白卡。舊版（白底、左側目錄）寫的 md 照樣能跑，產出來就是新樣子。

## 規則三：先改寫、再產頁

### 先分頁面型態

| 型態 | 例子 | 怎麼處理 |
|---|---|---|
| 決策頁、解說頁 | 計劃、提案、報告、比較、要對方拍板的頁 | 照下面的寫法重寫成好讀的版本再產頁，不要把工作稿直接丟進產生器 |
| 原文審稿頁 | 合約、完稿文案、逐字稿、客戶給的稿 | 內文一個字都不動，產頁加 `--no-lint`；最多在最前面加一個首屏，說明這頁要看什麼。加了 `--no-lint` 會自動用簡單版：首屏縮小、內文整份放一張白卡 |

### 決策頁、解說頁的寫法

1. **第一屏講完**：用 ` ```首屏 ` 寫一句話結論、要讀者做的幾件事、期限（語法見〈新寫法〉）。背景放後面，讀者不往下捲也知道要做什麼。
2. **一件事只講一次**：首屏講過的，內文不換句話再講；圖或表格講過的，下面不再用段落重述。不寫「總結」「小結」段。
3. **白話**：用讀者平常講的詞。專有名詞第一次出現就用比喻，或用 `> [!白話]` 補一句解釋。檔名、程式名、代號不進內文。
   - 指一群人或一批東西寫「誰、什麼時候、做什麼」，不要用 A1、甲乙、G2 這類代號，選項文字和表格欄位也一樣。
   - 英文縮寫換中文全稱；給客戶看的字用客戶的詞，不用自己團隊的內部用語。
   - 審查或建議類每條寫四格：這是什麼、為什麼是問題、不修會怎樣、怎麼修。
4. **能畫就不寫**：先問「這段在講哪一種關係」，照下表挑元件。純文字一段最多三行；每個 `##` 段落至少一個圖像元件、表格或題目卡。
5. **短**：一句一個重點。刪掉「換句話說」「也就是說」「值得注意的是」這類起手式，連同後面那句重講。
6. **刪的是重複，不是資訊**：數字、日期、名稱、後果一個都不能少、不能改。元件一格放不下的細節，在元件下面補一句，或用 `> [!說明]` 接著講。

### 圖像元件速查

寫幾行短語法，圖由產生器畫。分隔用全形 `｜`，箭頭用 `→`。完整寫法看 `assets/example.md`。

| 這段在講什麼 | 元件 | 語法 |
|---|---|---|
| 舊 vs 新、現在 vs 改完後 | 對照 | ` ```對照 `：第一行 `現在 → 改完後`，之後每行 `項目｜舊的 → 新的`（`項目｜` 可省） |
| 系統怎麼組成、資料怎麼流 | 架構 | ` ```架構 `：每行一層 `層名｜盒子、盒子`；層內有先後寫 `甲 → 乙`；兩層之間可插一行 `↓ 說明` |
| 什麼時候發生什麼 | 時間軸 | ` ```時間軸 `：每行 `時間｜標題｜說明`；行首 `✅` 已完成、`👉` 現在 |
| 先後順序、操作步驟、因果鏈 | 步驟 | ` ```步驟 `：每行 `標題｜說明`，自動編號；四步以內橫排、五步以上直排 |
| 幾個關鍵數字 | 數字 | ` ```數字 `：每行 `數字 單位｜標籤｜小註`；單位跟數字之間空一格才會變小字 |
| 幾個方案、誰做什麼、並列條目 | 卡片 | ` ```卡片 `（也可寫 `選項`、`分工`）：每行 `標題｜一行｜一行`；行首 `★` 標成建議方案；4 張排 2 乘 2，其餘三欄 |
| 多欄比較 | 表格 | 一般 md 表格。表頭同時有「現在／舊」與「改完後／新／建議」時，舊欄自動轉灰、新欄淡綠；整欄都是金額或數字時不折行 |
| 有分支的流程 | 流程卡片 | ASCII 或 mermaid 流程圖（graph／flowchart 的 TD、LR）；轉不準的會保留原樣。信件、範本這類純文字放 ` ```text ` 不會被動到 |
| 注意、風險、完成、白話解釋 | 重點框 | `> [!注意] 標題`，下一行起 `> 內容`。可用：注意、風險、完成、白話、說明 |
| 狀態 | 色標 | 行內 `{綠:已完成}` `{黃:等你}` `{紅:卡住}` `{藍:進行中}` `{灰:不做}`，表格裡也能用 |
| 一句裡的關鍵字 | 重點線 | `==關鍵字==`，一段最多一處 |
| 幾張圖並排 | 圖片 | 連續幾行只放 `![說明](路徑)`，會左右並排（改前改後對照不用上下捲） |

- 顏色有固定意思，不當裝飾：深藍是結論與要讀者做的事、綠是完成與建議與改完後、黃是注意與等待、紅是風險與還沒查證。全頁最重的框是題目卡，其他元件不要搶它。
- 結論與要讀者決定的事寫在首屏與題目卡，不用重點框。舊寫法的 `> [!結論]`、`> [!要你決定]` 還能用，沒寫首屏時產生器會拿開頭的 `> [!結論]` 組一個首屏。
- 語法寫錯不會壞頁，只會退回成灰底程式碼區塊；產完看一眼有沒有該變成圖卻還是灰底的。
- 有先後或因果用步驟、時間軸；互不相干才用卡片。
- 圖裡的字都是真文字，一樣能框選評論。

## 新寫法：首屏、段落、題目、待辦、明細

五種寫法都寫在 md 裡，分隔用全形 `｜`。內容本身要出現全形直線時寫 `\｜`。

### 首屏（每頁一個，放最前面）

````markdown
```首屏
眉標｜誰的事｜這頁是什麼
結論｜一句話結論，會變成全頁最大的字
補充｜最多兩句，講為什麼
要你｜2 題｜要你選，題目就在相關那一段下面｜#q1
要你｜1 件｜要你動手的事｜#todo
期限｜什麼時候前要回，回了之後我會做什麼
```
````

- `要你` 一行一張小卡：`數字｜說明｜點了跳去哪`。跳到第幾題寫 `#q1`、`#q2`，跳到待辦寫 `#todo`。
- 沒有要讀者做的事也要寫一行講明白，例：`要你｜0 件｜這頁只是讓你知道`。
- 結論不超過 30 個字。

### 段落：`## 眉標｜結論式標題`

- 眉標是兩到五個字的段名（會進浮動目錄），標題寫成一句結論，例：`## 時程｜6 週上線，現在在第 1 週的提案確認`。
- 段落自動編號。有題目或待辦的段落，目錄那一列會顯示「要答 2 題」「待辦 1 件」，答完變成「已答」。
- 只寫 `## 標題` 也可以，只是目錄與段首少一個段名。
- 一頁最多八段。超過就是塞了兩件事，拆成兩頁。

### 題目（要讀者決定的事）

````markdown
```題目
選哪個方案｜單選
說明｜這題的補充，可以省略
★ 建議方案：訂單＋庫存＋排班｜48,000 元｜三件事一次收齊
基本方案：訂單＋庫存｜36,000 元｜排班照舊用紙本
```
````

- 第一行 `標題｜單選` 或 `標題｜複選`，題號自動編。
- `★` 開頭的是建議選項，會有綠色「建議」標記，排第一個並寫清楚選了會怎樣。
- 選項寫三格 `選項｜小標籤｜說明` 時，中間那格變成灰色小標籤（例如價格）；寫兩格就是 `選項｜說明`。
- 複選題一定要有一個 `✕` 開頭的互斥選項（例：`✕ 先都不加`），不然分不出「還沒答」跟「都不要」。可以加一行 `全選｜按鈕上的字`。
- **題目放在它依據的那一段最後面，不集中在頁尾。** 同一件事不要表格列一次、題目再列一次，直接把那幾項寫成選項。
- 每個選項都要有名稱加一句說明，能獨立看懂，不要只寫代號、檔名、「是」「否」。要讀者點進去看的附網址。
- 要寫理由的不做輸入框，請讀者框選那一題留評論。框選選項裡的字不會誤勾。
- 舊寫法的 `- [ ]` 方框照樣會變成可勾的方框、跟著一起匯出；新頁一律寫題目卡，才有進度、「下一件」與「還沒答」的區分。

### 待辦（放最後一段）

````markdown
```待辦
你｜答完兩題，按「複製結果」傳給我｜有意見的地方直接框選留評論
我｜收到後 2 天內寄合約｜依你選的方案寫進去
```
````

- `你` 的那幾行可以打勾，做完勾起來，複製結果時會帶「標記做完的事」。
- 沒有要讀者做的就不寫 `你` 的行，頁面會自己顯示「這輪沒有要你動手的事」。

### 明細（預設收起）

````markdown
```明細 每週回報會看到什麼
這裡寫一般的 md，點了才展開。
```
````

- 算法、來源、名單、自己會處理的事放這裡。讀者拍板用得到的事實不要收進明細。
- 讀者在明細裡留的評論，之後點評論會自動把明細打開。
- 明細裡寫一般的 md（段落、清單、表格），不能再放別的圍欄（對照、步驟、題目這些）。

### 浮動目錄（產生器自動加，不用寫）

- 有題目或待辦的頁，底部一直有一條進度列：「目錄」、還剩幾件、「下一件」跳到下一個還沒答的、「複製結果」。沒有題目的頁，目錄改成右下角的浮動鈕。
- 點開目錄是浮層（手機是從底部升起的抽屜）：列出每一段、標出現在看到哪一段、每段還剩幾題。點某一段就跳過去並收起。
- 只有這一套導覽，不要自己在頁面加黏頂列、側欄或回到頂端鈕。

## 版面體檢（產生器自動印，只提醒不擋）

產頁時會印「版面體檢」：開頭沒有結論（沒寫首屏）、某段全是文字太長、圖像元件太少、單段太長、繞圈詞、破折號、檔名與程式碼字樣太多、同一件事講兩次（會列出是哪兩句）。有提醒就改 md 重跑，直到出現「版面體檢：通過」；判斷後要保留的，交付時講一句原因。原文審稿頁加 `--no-lint`。

## 省資源

- 圖一律用短語法，不手刻 HTML 或 SVG，不另外生圖。
- 要改內容就改 md 重跑，不要直接改輸出的 HTML。
- 明細、清單、附錄用 ` ```明細 ` 收起來；整頁都是長清單時用 `--fold "3"`。

## 執行流程

### Step 1：確認來源與身份

從對話判斷，判斷不出來再問：

- 要預覽什麼？照〈先分頁面型態〉分好。
- 誰會評論？身份預設 `我,訪客`。要給客戶看就改成例如 `客戶,我`（第一個是預設身份）。

來源是對話裡的內容時，先存成 md 檔，放在使用者目前的工作資料夾（沒有就放桌面上的 `預覽` 資料夾），檔名用中文描述內容，例如 `提案-範例客戶.md`。

### Step 2：產頁

**來源是 md（最常見）**：

```bash
python3 "$SKILL_DIR/scripts/md-to-preview.py" "<來源>.md" "<輸出>.html" \
  --identities "我,訪客" --key pc_<頁面名稱>
```

| 參數 | 作用 |
|---|---|
| `--identities` | 身份清單，逗號分隔，第一個是預設 |
| `--key` | 評論與作答存在瀏覽器裡用的名稱，每頁唯一；不給就用輸出檔名。作答另存在 `<這個名稱>__state` |
| `--title` | 文件標題；不給就用 md 第一個 `#` 標題 |
| `--fonts copy`／`none`／`link` | 字型處理，預設 `copy`（HTML 旁邊放 `preview-fonts/`）；`none` 用裝置內建中文字，整頁只有一個檔 |
| `--badges` | 首屏上方的小標籤，逗號分隔；首屏寫了 `眉標` 就不用給 |
| `--no-lint` | 不做版面體檢，並改用原文審稿的簡單版（內文一張白卡）；合約、完稿這類原文用 |
| `--layout sections`／`sheet` | 手動指定版面：`sections` 每個 `##` 一段並編號，`sheet` 內文整份放一張白卡。平常不用給，產生器自己判斷 |
| `--round` | 第幾輪審稿，會寫進匯出的機器碼；不給是 1 |
| `--fold "3,4"` | 把指定層級的標題收成可展開的段落，長清單頁用 |
| `--no-overlay` | 不加評論功能的乾淨版 |
| `--icon` | 分頁小圖示上的字或 emoji；不給就用標題第一個字 |

字型：🚨 用預設 `copy` 時，**要傳給別人就把 HTML 和 `preview-fonts/` 資料夾一起打包**，只傳 HTML 會掉回系統字（還是能用，只是比較不好看）。只有自己看、或想要單一檔案方便傳，就加 `--fonts none`。

圖片：md 裡獨立一段的 `![說明](img/檔名.jpg)` 會變成帶圖說的圖，路徑相對於輸出的 HTML，分享時跟 HTML 一起帶走。

**來源已經是排好版的 HTML（例如自己做好的提案頁）**：不改版面，只加評論功能。

```bash
python3 "$SKILL_DIR/scripts/convert/inject.py" "<頁面>.html" -o "<頁面>-評論版.html" --identities "我,客戶"
```

- `-o` 必須是新檔，工具不會覆蓋來源。
- 頁面已經有評論功能要換新版，加 `--replace`。
- 頁面沒有 `#doc` 時，整頁都能評論。

### Step 3：檢查，再打開給使用者看

交出去前自己看一眼：首屏有沒有結論、要讀者做的事、期限；該是圖的地方有沒有變成圖；題目是不是在依據旁邊。版面體檢要「通過」（原文審稿頁除外）。

用系統預設瀏覽器打開：

```bash
# macOS
open "<輸出>.html"
# Windows（Claude 的終端機是 Git Bash，用 start；PowerShell 改用 Start-Process "<輸出>.html"）
start "" "<輸出>.html"
# Linux
xdg-open "<輸出>.html"
```

告訴使用者三件事：

1. 題目直接點選項作答，底部「下一件」會跳到還沒答的。
2. 框選任何文字就會跳出「新增評論」。
3. 看完按底部「複製結果」（或右上「複製全部」），把內容貼回對話。

### Step 4（選配）：給客戶評論

- 身份設成客戶的角色，例如 `--identities "客戶,我"`。
- 用預設字型時，把 HTML 和旁邊的 `preview-fonts/` 資料夾一起壓縮成 zip 傳給客戶；加了 `--fonts none` 就只要傳 HTML。請客戶雙擊 HTML 打開。
- 評論和作答存在客戶自己的瀏覽器裡，不會自動同步回來。請客戶看完按「複製結果」，把文字用 email 或訊息傳回。

## 收到結果時

使用者貼回來的「評論彙整」依序是：每題答案、標記做完的待辦、舊式方框的勾選結果、一段 ` ```pv-decisions ` 機器碼、框選評論。

1. 整份原文先存成一個檔案，之後照這份做，不要憑記憶重打。要用程式處理就讀機器碼那一段。
2. 沒答的題目就是維持原樣，不要自己補判斷。
3. 同一題勾了互相矛盾的選項要回頭問，不要猜。也檢查選項之間的連動（例如保留的東西連到要刪的東西），列出來讓使用者知道。
4. 會影響對外的動作（寄信、刪檔、上線），先列出最後清單，使用者說「照做」才動手。

### 框選評論怎麼套用

每則評論有被框選的原文（引文）、位置（段落標題或第幾題）、前後文和評論內容。

| 評論長相 | 解讀 |
|---|---|
| 只有一段新文字、沒有動詞 | **替換**：把引文換成評論文字 |
| 「刪除」「去掉」 | 刪掉引文那段（只刪引文範圍） |
| 「加入」「補」「下面多一個」 | **新增**：在引文附近加內容 |
| 描述型（「可以…嗎」「希望…」） | 照需求修改 |
| 模糊、兩種讀法都通 | 選改動最小的做法，回報時說清楚你選了哪種 |

- 先用「位置」和「前後文」找到正確的那一處再改。同一段文字在頁面出現好幾次時，用前後文確認只對到一處。
- 同一輪評論可能跟上一輪重複，先比對哪些已經改過。

### 套用、重跑、重開

1. 改 md 原稿，再用**同一條指令、同一個 `--key`** 重跑產生器，不要直接改輸出的 HTML（下次重跑會被蓋掉）。同一個 key，舊評論和作答才接得回來。下一輪審稿可以加 `--round 2`。
2. 重新打開頁面給使用者看。
3. 回報：逐條列「哪一則 → 改了什麼」，模糊的標註你的選擇。

## 技術備忘（給 Claude，不用講給使用者聽）

- 評論錨定用「框選文字＋前後文」，內容小改也能重新對到位置，找不到就標「原文已變動」。
- 高亮用瀏覽器的 CSS Custom Highlight API，不改動頁面結構。Chrome、Edge、Safari 新版都支援；不支援的瀏覽器只會少了黃色高亮，側欄評論照常。
- 評論與作答分開存在瀏覽器 localStorage：評論在 `--key`，作答在 `<key>__state`。按「清空」只清評論，不清作答。每頁用不同的 `--key`，否則不同頁的評論會混在一起。
- 單選題用 checkbox 模擬，才能再點一次取消；互斥與全選由 `runtime.js` 處理。
- 評論介面載入後提供 `window.PreviewComments`：`.refresh()` 重新定位高亮、`.data()` 取出所有評論、`.exportMd()` 回傳匯出的 markdown。`window.PreviewPage.exportMd()` 只取作答那一段（含機器碼），`.state()` 取目前作答狀態。
- `runtime.js` 透過 `window.previewExtraMd` 把作答結果交給評論介面，所以「複製結果」和「複製全部」是同一份內容。改 `runtime.js` 時不要寫出直接賦值給評論設定物件的寫法，`inject.py` 會把它誤讀成設定（所以檔案裡用字串拼出設定名稱）。
- 疊放順序：進度列 30、目錄鈕 36、目錄浮層 38，都低於評論工具列 9000、評論側欄 10400、新增評論按鈕 10500。頁面自己的彈窗 z-index 要低於 10400，評論按鈕才不會被蓋住。
- 頁面自己的固定元件 `top` 引用 `var(--pco-bar-h, 0px)`，讓出頁頂評論工具列（乾淨版沒有工具列，自動退回 0）。
